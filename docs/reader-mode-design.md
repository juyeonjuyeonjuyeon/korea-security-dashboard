# 내부 읽기모드·자동 번역 설계

- 작성일: 2026-08-01
- 상태: 부분 구현(개인 확장 설치와 실제 Chrome 언어팩 검증 필요)
- 범위: 안보·기술 뉴스, 스크랩 및 사용자가 직접 여는 외국어 웹페이지

## 채택된 사용 범위

- 읽기 결과는 소유자의 브라우저에서만 표시하고 공개 사이트 데이터로 배포하지 않는다.
- 기사뿐 아니라 일반 외국어 홈페이지도 한국어로 번역해 읽을 수 있게 한다.
- 사용자가 정상적으로 열람할 수 있는 화면만 처리하며 로그인·유료벽·접근 제한은 우회하지 않는다.

## 구현된 범위

- `reader.html`, `reader.js`, `reader.css`: URL 입력, 원문 요청, 문단별 기기 내 한국어 번역, 진행률, 한국어·원문·나란히 보기, 개인 캐시
- `extension/`: Chrome Manifest V3 개인 확장, 숨은 탭 원문 추출, 리더 페이지 전달, 현재 페이지를 리더로 보내는 확장 버튼
- `app.js`, `tech.js`, `scrap.js`: 주요 뉴스·관련 뉴스·기술 뉴스·스크랩 제목을 내부 읽기 페이지로 연결
- `sw.js`: 읽기모드 파일을 PWA 오프라인 캐시에 포함

번역은 데스크톱 Chrome 138 이상의 내장 Translator API를 사용한다. 본문과 번역문은 외부 번역 서비스로 보내지 않으며, 번역 캐시는 해당 브라우저의 주연뉴스 사이트 저장소에만 남는다.

확장 설치 방법은 `extension/README.md`에 기록했다. 압축해제 확장 설치는 사용자 브라우저에서 직접 승인해야 하므로 자동 설치하지 않는다.

## 현재 상태

- 앱은 GitHub Pages에 배포되는 정적 PWA다.
- `app.js`, `tech.js`, `scrap.js`의 기사 링크는 외부 원문을 새 탭으로 연다.
- 브라우저에서 임의 언론사 본문을 직접 가져오면 CORS, 봇 차단, 유료벽에 막힐 수 있다.
- 정적 프런트엔드에 번역 서비스 API 키를 넣으면 방문자에게 노출된다.

## 권장 제품 경험

기사 제목을 누르면 먼저 사이트 내부의 `reader.html?id=<article-id>`로 이동한다. 읽기 화면은 다음 순서로 보여준다.

1. 한국어 제목, 출처, 발행 시각, 신뢰도 등급
2. **AI 번역·요약**임을 알리는 고정 표시
3. 한국어 핵심 요약 3~5개와 번역 발췌문
4. 원문 언어 제목 및 원문 링크
5. 수집·번역 시각과 본문 제공 범위

사용자는 읽기 화면에서 `원문 보기`, `스크랩`, `목록으로`를 선택할 수 있다. 원문 확보에 실패한 기사는 내부 화면에서 제목과 기존 요약만 표시하고 원문 링크를 우선 제공한다.

## 권장 아키텍처

### 채택안: 내부 읽기 페이지 + 개인 브라우저 확장

정적 GitHub Pages만으로는 다른 사이트의 HTML을 안정적으로 읽을 수 없다. 개인 브라우저 확장에 사이트 접근 권한을 부여하고 아래처럼 연결한다.

```text
주연뉴스의 뉴스 링크 또는 사용자가 입력한 URL
  → 주연뉴스 reader.html 열기
  → 개인 확장이 대상 탭의 실제 표시 문서 읽기
  → 기사형 페이지는 본문 추출, 일반 페이지는 주요 텍스트 구조 보존
  → 문단 단위 번역 및 캐시
  → reader.html에 한국어 전문 표시
```

- 주연뉴스 안에서는 기사 제목을 `reader.html?url=<encoded-url>`로 연결한다.
- 확장이 설치되지 않았으면 설치 안내 대신 원문 보기 버튼을 표시해 기존 기능을 유지한다.
- 기사형 문서는 제목·작성자·날짜·본문 중심의 읽기모드로 정리한다.
- 일반 홈페이지는 제목, 문단, 목록, 표, 링크 구조를 가능한 범위에서 유지한다.
- 번역문과 원문 문단을 일대일로 저장해 `한국어`, `원문`, `나란히` 보기를 지원한다.
- 이미 번역한 페이지는 URL과 콘텐츠 해시를 키로 개인 브라우저에 캐시한다.

번역 처리는 두 가지 배치가 가능하다.

- **로컬 번역:** 개인 PC의 로컬 모델 또는 로컬 번역 서비스를 사용한다. 개인정보 보호와 비용 면에서 유리하지만 PC 성능과 번역 품질의 영향을 받는다.
- **외부 번역 API:** 품질과 속도가 안정적이지만 비용이 발생한다. API 키는 공개 GitHub Pages가 아니라 개인 확장의 보호 저장소 또는 로컬 중계 프로그램에서만 관리한다.

페이지 전체를 한 번에 번역하지 않고 제목·문단·목록·표 셀 단위로 나눠 순차 처리한다. 첫 화면의 문단을 먼저 보여주고 나머지는 뒤에서 번역하면 긴 홈페이지도 빠르게 읽기 시작할 수 있다.

### 대안: 정적 사전 생성 방식

기존 GitHub Actions 수집 과정에 아래 처리를 추가하는 방식이 우선안이다.

```text
RSS·공식 API·허용된 웹 문서
  → 본문/발췌 추출
  → 언어 감지
  → 한국어 번역·요약
  → JSON 저장
  → GitHub Pages의 내부 읽기 화면에서 표시
```

- 기사마다 URL 기반의 안정적인 `articleId`를 만든다.
- 목록 JSON에는 읽기 화면에 필요한 요약 메타데이터를 넣는다.
- 긴 본문은 `data/articles/<articleId>.json`으로 분리해 첫 화면 용량을 줄인다.
- 번역은 같은 원문 해시가 존재하면 다시 생성하지 않는다.
- 번역 실패 시 원문 제목과 원문 링크만으로 정상 폴백한다.

권장 데이터 예시:

```json
{
  "articleId": "sha256-url-prefix",
  "url": "https://source.example/article",
  "source": "Example News",
  "publishedAt": "2026-08-01T09:00:00Z",
  "titleOriginal": "Original title",
  "titleKo": "한국어 제목",
  "summaryKo": ["핵심 내용 1", "핵심 내용 2"],
  "excerptKo": "허용 범위의 번역 발췌문",
  "contentMode": "summary",
  "language": "en",
  "translatedAt": "2026-08-01T09:10:00Z",
  "translationProvider": "configured-provider"
}
```

`contentMode`는 다음처럼 구분한다.

- `full`: 공개 라이선스·공식 발표 등 전체 재게시가 허용된 자료
- `excerpt`: 짧은 인용과 번역 발췌만 허용
- `summary`: 자체 작성한 한국어 요약만 제공
- `link-only`: 제목·출처·원문 링크만 제공

### 대안: 서버리스 온디맨드 번역

최신 기사 즉시 번역이 꼭 필요해질 때만 서버리스 중계 계층을 추가한다. 이 계층이 본문 추출, 번역 API 호출, 캐시와 사용량 제한을 담당한다. 프런트엔드는 비밀 키를 소유하지 않는다. 무료·단순 운영을 우선한다면 1단계만으로 시작한다.

## 개인용 전체 번역의 경계

- 번역 전문은 개인 브라우저 저장소에만 보관하고 저장소, GitHub Actions 산출물, 공개 JSON에는 올리지 않는다.
- 번역 결과를 다른 사용자에게 제공하거나 검색엔진에 노출하지 않는다.
- 페이지가 허용한 정상 로그인 상태는 사용할 수 있지만 접근 제어를 해제하거나 유료벽을 우회하지 않는다.
- DRM 미디어, 캔버스에 그려진 글자, 교차 출처 iframe, 일부 PDF 뷰어는 일반 HTML처럼 추출되지 않을 수 있다.
- 댓글·광고·탐색 메뉴는 기본적으로 제외하되, 일반 홈페이지 모드에서는 사용자가 포함 범위를 선택할 수 있게 한다.

## 저작권·품질 원칙

- 일반 언론 기사의 전체 본문을 복제·번역해 재게시하는 기능은 기본값으로 삼지 않는다.
- 기본 제공물은 자체 생성한 요약과 필요한 범위의 짧은 발췌로 제한한다.
- 전체 번역은 정부·기관 공개자료, 명시적 재사용 라이선스, 계약된 피드처럼 권리가 확인된 출처에만 허용한다.
- 모든 번역 화면에 자동 번역임을 표시하고 원문을 최종 기준으로 안내한다.
- 인명, 기관명, 군사·안보 용어는 용어집을 적용하고 숫자·날짜·단위를 원문과 대조한다.
- 원문 변경 또는 삭제 시 캐시 갱신·삭제가 가능하도록 원문 URL과 콘텐츠 해시를 보존한다.

## 오류와 예외 처리

- CORS 우회용 공개 프록시는 개인정보·가용성·보안 문제 때문에 사용하지 않는다.
- 로그인·유료벽·robots 정책으로 접근할 수 없는 본문은 우회하지 않고 `link-only`로 처리한다.
- 추출된 페이지가 쿠키 안내나 메뉴뿐이면 품질 검사를 통과시키지 않는다.
- 번역 결과 안의 HTML은 신뢰하지 않으며 일반 텍스트로 렌더링한다.
- 원문 URL은 `http`와 `https`만 허용하고, 내부 리더의 ID로 임의 파일 경로를 만들지 않는다.

## 구현 순서

1. 개인 브라우저 확장의 지원 브라우저와 번역 방식(로컬/API) 결정
2. `reader.html`의 모바일 우선 화면과 확장 통신 규약 정의
3. 기사 본문 모드와 일반 홈페이지 구조 보존 모드 구현 계획 확정
4. 문단 단위 번역 큐, 진행 상태, 중단·재시도, 개인 캐시 설계
5. 안보면·기술면·스크랩의 링크를 내부 읽기 URL로 통일
6. 원문 보기, 원문/번역/나란히 보기, 용어집과 오류 폴백 검증

## 완료 기준

- 안보면, 기술면, 스크랩에서 같은 기사가 동일한 내부 읽기 URL로 열린다.
- 지원 기사에는 한국어 요약과 원문 링크가 함께 표시된다.
- 번역·본문 수집 실패가 목록 또는 읽기 화면을 깨뜨리지 않는다.
- 비밀 키가 GitHub Pages 산출물과 저장소에 포함되지 않는다.
- 유료벽이나 접근 제한을 우회하지 않는다.
- 공개 배포 데이터의 전체 본문 표시는 재게시 권한이 확인된 출처에만 적용된다.
- 개인용 전체 번역은 공개 배포 파일이 아니라 소유자의 브라우저에서만 생성·보관된다.
- 긴 일반 홈페이지도 첫 번역 문단부터 점진적으로 표시되고 진행 상태를 확인할 수 있다.

## 보류 사항

- 로컬 번역과 외부 번역 API 중 사용할 방식
- 우선 지원 브라우저와 개인 확장의 배포 방식
- 개인 번역 캐시의 용량·보존 기간·일괄 삭제 UI
- 번역 결과의 보존 기간과 삭제 요청 처리 방식
